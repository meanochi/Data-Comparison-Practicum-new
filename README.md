# API להשוואת נתוני תקופות עבודה — PDF מול נתוני טבלה זמנית

API שמפענח ומשווה נתוני "פירוט תקופות עבודה" בין שורות טבלה זמנית (או קובץ
DAT) לבין קובץ PDF (דו"ח סיכום נתוני פרישה), לפי מספר זהות. הפרויקט בנוי
לפי תבנית ה-API הסטנדרטית של הארגון (Node.js + TypeScript + Express).

## התקנה והרצה

דרוש Node.js 18 ומעלה.

```bash
npm install
cp .env.example .env
npm run dev     # פיתוח, עם ריענון אוטומטי
npm start       # הרצה רגילה
npm run build   # קומפילציה ל-build/
npm test        # בדיקות אוטומציה
```

`GET /api/healthcheck` — בדיקת חיות.

תיעוד אינטראקטיבי של ה-API (Swagger UI): `/api-docs` — מציג את החוזה המלא
(JSON ו-form-data) וכולל כפתור "Try it out" לשליחת בקשות ישירות מהדפדפן.
מקור התיעוד הוא `openapi.json`.

## POST /api/compare

הממשק עובד **אחד-על-אחד**: כל קריאה נושאת שורות טבלה של תעודת זהות אחת +
מסמך ה-PDF שלה.

```
POST /api/compare
Content-Type: application/json

{
  "rows": [
    { "MISPAR_TNUA": "9050", "MISPAR_ZEHUT": "012345678", "SUG_TKUFA": "9999",
      "TAARICH_ME": "01092010", "TAARICH_AD": "31082015", "ORECH_SHERUT": "06000",
      "SUG_ZECHUYOT_LEGIMLA": "02", "HEKEF_MISRA": "1000", "SEQ": 1 }
  ],
  "pdf": { "filename": "report_12345678.pdf", "content": "<PDF בקידוד base64>" }
}
```

- `rows` — שורות טבלת `LD_CHINUCH_9050_TKUFOT_RETSIF` של אותה ת"ז, כאובייקטים
  ששמות העמודות הם המפתחות שלהם. עמודות שאינן משתתפות בהשוואה (`KOD_PEULA`,
  `ZIHUY_NOSAF`, `SEMEL_MISRAD`, `LOAD_DATE`) מותרות ומתעלמים מהן; עמודת
  `SEQ` משמשת לזיהוי השורה בהודעות שגיאה ואזהרה. בקשה עם `pdf` בודד שמכילה
  יותר מת"ז אחת נדחית עם 400.
- `pdf` — מסמך סיכום הפרישה של אותה ת"ז, שם + תוכן ב-base64.

אותו חוזה נתמך גם כ-**multipart/form-data** (נוח לבדיקה מפוסטמן): שדה
`rows` כטקסט (מערך JSON) ושדה `pdf` כקובץ מצורף ממש.

מבנה התשובה:

```json
{
  "valid": 1,             // אינדיקציית תקינות: 1 - הכל תואם, 0 - אחרת
  "idNumber": "12345678", // הת"ז שנבדקה
  "rows": [ ... ],        // אותן שורות שנשלחו, על כל פרטיהן, בתוספת לכל שורה:
                          //   valid: 1/0, ו-reason עם פירוט הפער כשאינה תקינה
  "text": "..."           // טקסט מאוחד המרכז את כל התוצאות והפערים
}
```

בקריאה עם `?full=1` נוספים לתשובה גם `summary` / `warnings` / `results` —
הפירוט המלא של ההשוואה.

**זיהוי שורה עם שגיאה:** ההתאמה בין תקופות נעשית קודם לפי (תאריך התחלה,
תאריך סיום). תקופות שנשארו ללא התאמה מדויקת משני הצדדים מצומדות אם הן
כמעט זהות — נדרש לפחות תאריך אחד זהה ועוד שני שדות תואמים — ואז הן מדווחות
כשורה שגויה אחת עם פירוט ההבדלים, במקום "קיימת רק בנתונים" + "קיימת רק
במסמך".

## כללי השוואה שסוכמו

1. **התאמת שורות** לפי (תאריך התחלה, תאריך סיום); לאחר מכן מושווים סוג
   תקופה, אורך שירות, סוג זכויות והיקף משרה.
2. **עזיבה / אין העסקה (קוד 4):** בדרך כלל שורות מסוג זה אינן מודפסות
   בדו"ח ה-PDF, אך לעיתים כן מודפסות (בתווית "אין העסקה") — משני הצדדים
   (נתונים או PDF) תקופה כזו אינה משתתפת בהשוואה כלל ואינה נספרת כפער;
   היא מוצגת ב-`excluded` לידיעה בלבד.
3. **שבתון:** תווית "שבתון" בעמודת סוג תקופה ב-PDF תואמת בנתונים לקוד סוג
   תקופה 2 (חל"ת) בשילוב קוד סוג זכויות 67 (שבתון מורים).
4. **תוויות מרובות-קודים:** למשל "לא נושא זכויות" ב-PDF יכולה להתאים לקוד 10
   או 13. תווית שלא מוכרת למערכת מסומנת כאי-התאמה עם אזהרה מפורשת לעדכן את
   המיפוי ב-`src/mappings.ts`.
5. **מספרי זהות** מנורמלים ללא אפסים מובילים (ב-PDF מודפס בלי אפס מוביל).
6. **בדיקת שפיות:** אם נמצאות לאותה ת"ז שתי תקופות עם אותם תאריכי התחלה
   וסיום — מוצגת אזהרה (לא אמור לקרות).

## מבנה הפרויקט

```
app.ts                              # נקודת כניסה
IController.ts                      # מחלקת בקר בסיס
openapi.json                        # מקור תיעוד ה-Swagger של POST /api/compare
src/
  startApp.ts                       # אתחול אפליקציית Express (כולל /api-docs)
  components/compare/
    compare.controller.ts           # POST /api/compare
    compare.service.ts              # הלוגיקה העסקית: פענוח, השוואה, בניית תשובה
  comparator.ts                     # מנוע ההשוואה
  mappings.ts                       # טבלאות קודים ומיפוי PDF -> DAT
  tableSource.ts                    # פענוח שורות JSON מהטבלה הזמנית - מקור הנתונים היחיד של ה-API
  parsers/
    datParser.ts                    # עזרים משותפים (נרמול ת"ז, תאריך, בדיקת כפילויות)
    pdfChinuchParser.ts             # פרסר דו"ח "סיכום נתוני פרישה"
  pdfText.ts                        # חילוץ טקסט גנרי מ-PDF (mupdf)
  middleware/                       # headers, error handling
  utils/                            # config, logger
test/                               # בדיקות אוטומציה (node:test + ts-node)
  helpers/sampleData.ts             # בניית שורות טבלה מ-samples/sample.dat לצורך בדיקות בלבד
samples/                            # קבצי דוגמה פיקטיביים לבדיקות
```

פענוח בייטים גולמיים של קובץ DAT (קידוד DOS-862, טעינה לטבלה) **אינו חלק
מהפרויקט הזה**: זהו שלב שקורה לפני קריאת ה-API (SQL*Loader בטעינה לטבלת
`LD_CHINUCH_9050_TKUFOT_RETSIF`) — ה-API עצמו תמיד מקבל JSON. `test/helpers/sampleData.ts`
מפענח את `samples/sample.dat` באופן מינימלי רק כדי להפיק נתוני בדיקה.

**הרחבת המערכת** (פורמט דוח PDF חדש, תווית חדשה, השוואה מסוג חדש) — ראו
את הערות התיעוד בראש `src/pdfText.ts` ו-`src/mappings.ts`.

## הערת פרטיות

תיקיית `samples/` מכילה נתונים פיקטיביים בלבד. אין לשמור בריפוזיטורי קבצי
אמת המכילים פרטים אישיים.
